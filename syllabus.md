## Competências

- Compreender os diferentes tipos de dados utilizados em ambientes analíticos e de Big Data.
- Gerenciar as possíveis alternativas computacionais para manuseio de dados em ambientes de Big Data.
- Evidenciar os requisitos para a arquitetura analítica e processos de ingestão e alimentação de dados.
- Compreender os principais componentes das arquiteturas modernas de dados (data lake, data warehouse, lakehouse, data mesh).
- Construir um data lake visando ao processamento de dados estruturados e não estruturados.
- Identificar arquiteturas de dados em ambientes cloud e distribuídos.
- Avaliar alternativas tecnológicas para armazenamento e processamento de dados em escala.

## Ementa

Introdução aos tipos de dados e ao contexto de Big Data. Fundamentos de Big Data e arquiteturas modernas de dados. Overview das ferramentas para o gerenciamento de dados distribuídos. Organização e manuseio de dados em bases distribuídas. Arquiteturas modernas: data lake, data warehouse, lakehouse e data mesh. Plataformas em cloud computing e pipelines de dados. Apache e outras ferramentas para processamento distribuído. Miniprojeto: construção e avaliação de data lake.

### Dinâmica alternativa/complementar para a Aula 2 — RPG "As Cinco Torres Isoladas"

Referência: `docs/Aulas-de-outros-cursos/Aula 8 Arquitetura de Dados/` (mesmo professor, originalmente material da disciplina "Gestão e Governança de Dados" — mas o conteúdo técnico é diretamente aplicável ao Módulo 2 desta disciplina, já que trata da escolha entre arquiteturas modernas de dados).

- **O que é:** um RPG de sala de aula, sem mestre, síncrono. A empresa fictícia **LODGov** (rede global de serviços profissionais com silos de dados entre RH, CRM, ERP e sistemas legados) apresenta o problema via falas dos C-Levels (CMO, CDO, CIO, CHRO, CEO), e o CTO (papel dos alunos) precisa escolher entre 5 "portas" arquiteturais:
  1. **Conselho Federado dos Domínios** (Data Mesh puro)
  2. **Lago Único do Conhecimento** (Data Lake/Lakehouse centralizado)
  3. **Colheita Silenciosa** (integração incremental sem blueprint)
  4. **Grande Ressaca** (rip-and-replace / big bang)
  5. **Tribunal das Leis** (governança antes da tecnologia)
- Cada porta tem armadilhas ocultas, custos ocultos e uma pontuação explicada em 3 eixos (Resiliência, Visão, Influência, de -4 a +4). Depois que os grupos escolhem e recebem as consequências narradas, o professor guia (com pistas progressivas) a descoberta de uma **porta secreta** — "Ponte dos Contratos" (data contracts + domain ownership com padrões mínimos + governança federada leve + Bronze descentralizado/Silver-Gold centralizado) — que é a síntese de maior pontuação e conecta diretamente com o conteúdo teórico do Módulo 2 (Data Mesh vs. Data Lake vs. Lakehouse vs. Data Fabric).
- **Por que usar aqui:** cobre exatamente a competência "Compreender os principais componentes das arquiteturas modernas de dados (data lake, data warehouse, lakehouse, data mesh)" de forma mais envolvente do que uma comparação expositiva, e antecipa a tensão entre autonomia de domínio e governança central que reaparece no Módulo 4 (miniprojeto de data lake da LODLog).
- **Como usar:** pode substituir o Lab 2 baseado na LODLog nesta oferta, ou ser aplicado como dinâmica de abertura (30–40min) seguida do Lab 2 original como aprofundamento técnico. Não é necessário adaptar o cenário para a LODLog — o RPG é agnóstico de empresa; a discussão de trade-offs vale por si.
- Material de apoio nessa pasta: `Aula 8 Arquitetura de Dados.md` (teoria DAMA-DMBOK sobre Arquitetura de Dados — definição, blueprint, drivers de negócio, papel de ponte entre negócio e tecnologia — útil como abertura conceitual do Módulo 1 ou 2), `Aula/As cinco torres isoladas.md` (roteiro completo do RPG com falas, portas, pontuação e narrativas de consequência), `5-learning-objetives.md` e `key-take-home.md` (objetivos de aprendizagem e pontos-chave já redigidos nesse mesmo formato do `syllabus.md`), `sala cto/cto-prob-comuns-arquit.md` (pesquisa sobre problemas reais de CTOs em arquitetura de dados em 2026, útil para contextualizar a relevância do tema).

## Hard rules

- As aulas iniciam às 19h e finalizam às 22h20min.
- Temos 15min de intervalo em cada aula.
- Cada aula deve ter metade teoria e metade prática. Programar os tempos de exposição e Lab para atender obrigatoriamente a essa regra.

## Avaliação

Disciplina isenta de prova, avaliada por trabalho (ver ementa oficial, seção "Disciplinas isentas de prova"). O trabalho usa o cenário da LODLog como estudo de caso único do Módulo 4 (miniprojeto: construção e avaliação de data lake), com duas entregas:

**Individual (70%) — Planejando o pipeline de dados para o data lake da LODLog:**
- Cenário sub-escolhido (rotas / manutenção preditiva / estoque / fraude) e fontes de dados mapeadas (mínimo 3–5, internas e externas).
- Análise dos 5 Vs para as fontes escolhidas.
- Arquitetura proposta (Data Lake ou Lakehouse) com camadas Bronze/Silver/Gold e justificativa batch vs. streaming.
- Prazo: 15 dias após a última aula.

**Em grupo (30%) — Apresentação na última aula:**
- Arquitetura simplificada do data lake, das fontes até o consumo.
- Integração de pelo menos uma fonte estruturada (ERP/WMS/TMS) e uma não estruturada/semiestruturada (sensores IoT, APIs externas).
- Resultado de uma análise conduzida sobre os dados do data lake.
- Avaliação pós-projeto: vantagens, limitações e lições aprendidas.

Referência de apoio (não obrigatória, mas alinhada ao mesmo universo): `docs/LODLog/Projeto-Eng-Dados-IA-para-Negocio.md` traz o detalhamento completo do cenário LODLog (dados de exemplo, DDL, queries e rubricas) usado por uma disciplina irmã do curso; adaptar o escopo ao foco desta disciplina em data lake (Módulo 4), sem exigir modelagem dimensional completa ou feature engineering para ML, que são objeto de outras disciplinas do curso.
